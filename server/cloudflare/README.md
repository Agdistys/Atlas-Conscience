# OùQuandQui routing relay — bounded free pilot

The owner authorized openrouteservice + Cloudflare on 27 November 2026, free plans only, with the website remaining on GitHub Pages. The isolated Worker is deployed at https://ouquandqui-routing.d-serant.workers.dev (28 November 2026). The owner confirmed both free plans through the protected local form; the existing authorization cannot inspect billing. No account-wide plan was changed. No subscription upgrade or change to another application is authorized.

Run `npm run test:cloudflare` from the repository: 80 tests cover the relay, global quota, local connector, selected-section planner and existing Node relay. Bundle check: `npm exec --yes --package wrangler@4.135.0 -- wrangler deploy --dry-run --config server/cloudflare/wrangler.jsonc`. This dry run does not publish.

The Worker accepts only two-point automobile routes, no alternatives or heavy-vehicle profile yet. It requests instructions and complete toll/category attributes from the fixed HeiGIT endpoint, validates them and returns only selected fields. The provider key stays in a Cloudflare secret. Missing attributes, exclusions not respected, upstream errors and uncertain instruction coverage fail closed. There is no automatic retry, private trip logging or paid fallback. A real public Lyon–Valence sample passed the complete free/selected/free calculation and exact geometry check through this relay. This single route is not general network, access, maneuver, caravan or Android qualification. The public app is not connected to this new relay.

A single SQLite-backed Durable Object reserves requests transactionally: hard ceilings of 100/day and 10 in a sliding minute, across instances and restarts. Failed provider attempts still count. The stored record contains only counts/timestamps. Origin restrictions are CORS protection, not user authentication; non-browser clients can spoof Origin and consume the capped allowance. This is a bounded pilot, not an unlimited public service.

The deployed configuration has `SERVICE_ENABLED` and `FREE_PLAN_CONFIRMED` set to true following the explicit owner attestations. Missing/false flags still close the service. These flags are an activation gate, not a mechanism that converts a paid account to free. Verify the account really uses Workers Free before deployment. SQLite Durable Objects are available on Workers Free; exceeding free limits stops operations. The current OAuth connection can inspect Workers settings but receives 403 for billing subscriptions, so the free-plan evidence is the owner’s explicit attestation, not an API billing check. Do not change subscriptions or global account defaults.

## Local connection

After loading `../ENVIRONNEMENT.sh` from the repository, run `node server/cloudflare/connect-local.mjs`. Open `http://127.0.0.1:18789` on this Mac. Create/open the free HeiGIT account, verify email, copy the Standard API key into the masked field, and explicitly confirm both free plans. No secret is requested in chat.

The loopback-only helper checks Host, Origin and a random session token. A click sends one public Lyon–Valence test to HeiGIT. If accepted, it writes `quality/cloudflare-routing/private/ors-connection.json` (0600 in a 0700 directory); the entire proof directory and `.dev.vars` are ignored by Git. The helper never returns or logs the key. It rejects duplicate submissions, never recreates a missing private directory, does not deploy and does not upgrade anything. Stop it when the connection is completed; after successful transfer to the Cloudflare secret, remove the temporary local credential and retain only redacted receipts.

Current proof: `quality/routing-live-20261128/worker-proof.json` (five valid calculations, restricted-access refusal, invalid body and denied origin). The key is stored only in the Cloudflare secret; the temporary credential was removed and the connector stopped. Worker fetch uses `redirect: manual` and explicitly refuses all 3xx responses, because Workers does not implement `redirect: error`. No key can follow a redirect. The planner uses the actual local HTTP receipt time for freshness; server timestamps remain separate to avoid clock drift.
